# 양피지 단서 상호작용 — Claude Code 작업 지침서

Oct 3, 2026 · @김진호

## 개요

씬에 있는 `parchmentFbx`를 코드로 돌돌 말린 상태로 변형하고, 바라보고 클릭하면 눈앞으로 다가와 살펴볼 수 있는 단서 상호작용을 만든다. 이 문서는 Claude Code가 Unity MCP를 사용해 코드 작성부터 에디터 설정, 플레이 테스트까지 진행하기 위한 지침이다.

**이번 작업 범위**

1. 양피지 말기: 평평한 양피지 메시를 정점 변형으로 말린 모양으로 만든다. 말림 정도는 0\~1 값 하나로 조절되며, 에디터에서도 바로 보여야 한다.
2. 바라보기 감지: 화면 중앙(조준점)이 가까이 있는 양피지에 닿으면 E키 상호작용 안내가 뜨고 외곽선이나 밝기로 강조된다.
3. 살펴보기: E키를 누르면 양피지가 부드럽게 카메라 앞으로 와서 마우스로 돌려볼 수 있다. 다시 E키를 누르면 원래 위치로 돌아간다.
4. 단서 획득: 처음 살펴볼 때 한 번만 단서를 획득 처리하고 획득 알림을 띄운다.

**이번 범위 밖 (만들지 않는다)**

- 양피지가 펼쳐지는 연출, 글자 표시. 단, 나중에 붙일 수 있게 연결 지점(이벤트, 말림 값)은 만들어 둔다.
- 단서 목록 UI(인벤토리 화면).
- 2인 협동 네트워크 동기화. 방식이 아직 정해지지 않았으므로 로컬 동작만 만든다.

## 공통 규칙

모든 단계에서 아래 규칙을 지킨다. 가장 중요한 것은 **0단계 분석 보고 후 승인을 받기 전에는 코드나 씬을 수정하지 않는 것**이다.

**환경**

- Unity 6000.6.0f1, URP, Input System 패키지(기존 `InputSystem_Actions.inputactions` 사용). 레거시 `Input.GetKey`는 쓰지 않는다.
- 1인칭 시점 확정. 화면 중앙을 조준점으로 삼는다.
- `FindObjectOfType` 대신 `FindFirstObjectByType` / `FindAnyObjectByType`를 쓴다. TextMeshPro는 Unity 6의 uGUI 패키지에 포함된 것을 쓴다.

**코드 작성**

- C#만 사용한다. 모든 클래스·메서드·필드·핵심 줄에 "무엇을 하는지"와 "왜 이렇게 했는지"를 한국어 주석으로 단다. 사용자는 Unity 초보이므로 문법보다 의도 설명에 무게를 둔다.
- Inspector 노출 필드는 `[SerializeField] private`로 하고, `[Tooltip]`과 기본값 단위(m, 초, 도)를 적는다.
- `GetComponent`는 `Awake`에서 캐싱하고, 시간 기반 이동에는 `Time.deltaTime`을 쓴다. 살펴보기 연출은 일시정지와 무관하게 `Time.unscaledDeltaTime`을 쓴다.
- 외부 트윈 라이브러리(DOTween 등)는 추가하지 않는다. 코루틴 + `AnimationCurve`로 처리한다.

**폴더와 기존 시스템**

- 새 스크립트는 `Assets/Scripts/KJH/Clue/`에 둔다. 에디터 전용 코드는 `Assets/Scripts/KJH/Clue/Editor/`.
- 단서 데이터 에셋은 `Assets/Data/KJH/Clue/`에 둔다(기존 `PhotoItemData` 에셋 위치 규칙이 다르면 그것을 따르고 보고한다).
- 이미 있는 `IInteractable`, `InteractionController`, `InteractionPromptUI`, `PhotoAcquiredToast`, `CameraModeController`(Photo 폴더)를 재사용한다. 같은 역할의 스크립트를 새로 만들지 않는다.
- 기존 사진 시스템(PhotoSpot, E로 진입·E로 촬영·Esc로 취소)의 동작을 깨뜨리면 안 된다. 수정이 불가피하면 보고 후 승인을 받는다.

**진행 방식**

- 단계별로 진행하고 각 단계 끝에 보고한다. 콘솔 에러·경고 0건을 확인한 뒤 다음 단계로 넘어간다.
- 원본 FBX 에셋과 원본 메시는 절대 덮어쓰지 않는다. 변형은 항상 복사본 메시에 한다.
- 씬 수정 전에 씬을 저장하고, 끝난 뒤 다시 저장한다.

## 0단계: 사전 분석 보고 (수정 금지, 보고만)

Unity MCP로 아래 항목을 조사해 표로 보고하고, 사용자 승인을 받은 뒤 1단계를 시작한다.

**양피지 모델 조사 (`parchmentFbx`)**

1. 계층 구조: `parchmentFbx` 자신에 MeshFilter가 있는지, 자식에 있는지. 실제 메시가 붙은 오브젝트 이름.
2. 메시 정보: 정점 수, 삼각형 수, 서브메시 수, 로컬 bounds 크기(x, y, z).
3. 판 모양 판별: bounds 중 가장 짧은 축 = 두께 축, 가장 긴 축 = 길이 축(말리는 방향), 나머지 = 폭 축(말린 원통의 축). 판단 결과를 보고한다.
4. 정점 밀도: 길이 축 방향으로 정점이 몇 줄 있는지. 부드럽게 말리려면 최소 40줄 이상이 필요하다.
5. 두께: 단면이 얇은 판(앞면만)인지, 두께가 있는 상자형(앞뒤 면 + 옆면)인지.
6. Transform: 위치, 회전, 스케일. 스케일이 1이 아니면 그 값.
7. FBX 임포트 설정: Read/Write Enabled 여부, Scale Factor, 머티리얼 개수.
8. 현재 콜라이더, Rigidbody 유무.

**기존 상호작용 코드 조사**

1. `IInteractable`의 메서드 목록과 위치(경로).
2. `InteractionController`가 대상을 찾는 방식(현재는 트리거 기반으로 알고 있음), 입력 처리 방식, "바쁜 상태"(IsBusy 등) 처리 방식.
3. `InteractionPromptUI`, `PhotoAcquiredToast`를 사진 외 다른 기능에서도 재사용할 수 있는 구조인지.
4. 플레이어 이동과 시점 회전 스크립트 이름, 그리고 그것들을 잠깐 멈출 수 있는 방법이 있는지(`CameraModeController`가 이미 쓰는 방식이 있으면 그것).
5. `Player/Interact` 액션의 현재 바인딩.
6. URP Volume 사용 현황(뷰파인더용 Volume이 있는지).

**보고 형식**

조사 결과 표 + 아래 결정이 필요한 항목에 대한 제안을 함께 낸다.

- 정점 밀도가 40줄 미만일 때: 코드로 세분화(subdivide)할지 제안.
- 상호작용 감지를 트리거 방식에서 "바라보기(레이캐스트)" 방식으로 확장하는 방법. 기존 PhotoSpot 동작을 유지하는 방안.
- 재사용할 것 / 수정할 것 / 새로 만들 것 목록.

## 1단계: 양피지 말기 (ParchmentRoller)

평평한 양피지 메시의 정점을 C# 코드로 나선형(아르키메데스 나선)으로 감아서 말린 모양을 만든다. Blender 리깅이나 셰이더 없이 Unity 안에서 끝나고, 말림 정도를 0\~1 값 하나로 조절하므로 나중에 이 값을 1→0으로 움직이기만 하면 "펼쳐지는 애니메이션"이 된다.

**이 방식을 고른 이유** (지난 기록에서 펼침 연출은 Shader Graph나 Blender 본으로 하자고 했으나 바꾼 이유)

- 메시가 하나뿐이고 정점 수도 적어서, CPU로 값이 바뀔 때만 다시 계산해도 성능 부담이 없다.
- 에디터 화면에서 슬라이더로 바로 확인할 수 있고, 셰이더와 달리 콜라이더와 bounds도 실제 모양을 따라간다.
- AI에게 "더 촘촘하게", "반대 방향으로"처럼 말로 수정을 요청하기 쉽다.

### 1-1. 정점 밀도 확보 (0단계에서 부족하다고 나온 경우에만)

- 에디터 메뉴 `Tools/KJH/Parchment/Subdivide Selected Mesh`를 만든다. 선택한 메시의 삼각형을 4개로 나누는 중점 분할을 반복해, 길이 축 방향 정점 간격이 길이의 1/60 이하가 될 때까지 진행한다.
- UV, 노멀, 탄젠트, 정점 색 등 모든 정점 속성은 보간해서 유지한다. 공유 정점은 중복 생성하지 않는다.
- 결과는 `Assets/Data/KJH/Clue/Meshes/parchment_subdivided.asset`으로 새로 저장한다. 원본 FBX는 건드리지 않는다.

### 1-2. ParchmentRoller 컴포넌트

`[ExecuteAlways]`로 에디터에서도 동작한다. 메시가 붙은 오브젝트(MeshFilter가 있는 오브젝트)에 붙인다.

| Inspector 항목 | 기본값 | 설명 |
| --- | --- | --- |
| sourceMesh | (자동) | 변형 전 원본 메시. 비어 있으면 Awake에서 현재 MeshFilter 메시를 저장 |
| rollAmount | 1 | 0 = 평평, 1 = 완전히 말림. `[Range(0,1)]` |
| coreRadius | 길이 × 0.03 | 가장 안쪽 심의 반지름 (m) |
| layerGap | 두께 × 1.2 (최소 0.0008) | 한 바퀴 돌 때마다 반지름이 커지는 양 (m). 겹이 서로 뚫고 지나가지 않게 두께보다 크게 |
| lengthAxis / widthAxis / thicknessAxis | 0단계 분석 결과 | 로컬 축 지정 (X, Y, Z 중) |
| rollFromMaxEdge | false | 길이 축의 어느 끝에서부터 말지 |
| rollTowardPositive | true | 두께 축의 어느 쪽으로 말려 올라갈지 (그림이 있는 면이 안/밖 중 어디로 갈지) |
| centerWhenRolled | true | 완전히 말렸을 때 원통이 원래 양피지 중심에 오도록 길이 축으로 보정 |

**변형 계산** (정점마다, 로컬 좌표 기준)

- `u` = 말기 시작 끝(자유단)에서 잰 길이 축 거리, `h` = 두께 축 좌표(가운데 면 기준), `w` = 폭 축 좌표는 그대로 둔다.
- 말린 길이 `S = rollAmount × 전체 길이`. `u < S`인 정점만 감고, 나머지는 평평하게 둔다.
- 심에서부터 바깥으로 감기는 나선의 반지름과 감긴 길이는 아래와 같다. φ는 심에서부터 돈 각도(라디안), a = coreRadius, b = layerGap.

```latex
r(\varphi) = a + \frac{b}{2\pi}\varphi \qquad s(\varphi) = a\varphi + \frac{b}{4\pi}\varphi^2
```

- 정점의 각도는 `s(φ) = u`를 φ에 대해 푼 근의 공식 값을 쓴다. 전체 각도 `Φ = s⁻¹(S)`, 바깥 반지름 `R = r(Φ)`.
- 원통 중심 `C = (길이축: S, 두께축: R)`. 접합부에서 안쪽으로 돈 각도 `θ = Φ − φ`일 때 위치는 `C + (r(φ) − h) × (−sin θ, −cos θ)`. θ = 0인 접합부에서 평평한 부분과 이어진다.
- 노멀과 탄젠트는 `RecalculateNormals`를 쓰지 않고, 원래 값을 폭 축 기준으로 θ만큼 회전한다. 앞뒤 면과 모서리 경계가 깨지지 않게 하기 위함이다.
- 변형 후 `RecalculateBounds()`를 호출한다.

**메시 관리 (초보자가 가장 실수하기 쉬운 부분)**

- 변형은 원본을 복사한 인스턴스 메시에 한다. 인스턴스는 `hideFlags = HideFlags.DontSave`로 만들어 씬이나 에셋에 저장되지 않게 한다.
- `OnEnable`에서 인스턴스를 만들고 적용, `OnDisable`에서 MeshFilter를 원본으로 되돌리고 인스턴스를 파괴한다. 그래야 씬을 다시 열어도 메시가 사라지지 않는다.
- 값이 바뀔 때만(`OnValidate`, 프로퍼티 setter) 다시 계산한다. `Update`에서 매 프레임 계산하지 않는다.
- 같은 오브젝트에 BoxCollider가 있으면 변형 후 bounds에 맞춰 크기와 중심을 갱신한다.

**나중을 위한 연결 지점**

- `public float RollAmount { get; set; }` 프로퍼티와 `AnimateRoll(float target, float duration)` 코루틴 메서드를 만들어 둔다. 이번 작업에서는 호출하지 않는다.

### 1-3. 1단계 확인

- 에디터에서 rollAmount 0, 0.5, 1일 때 각각 두 각도에서 스크린샷을 찍어 보고한다.
- 겹이 서로 뚫고 지나가지 않는지, 텍스처가 찢어지지 않는지, 바닥(책상 면)에 원통이 떠 있거나 묻혀 있지 않은지 확인한다.
- 씬을 저장 후 다시 열어도 말린 상태가 유지되는지 확인한다.

## 2단계: 단서 상호작용 (바라보기 → E키 → 살펴보기 → 복귀)

화면 중앙이 2m 안의 양피지를 가리키면 E키 안내가 뜨고, E키를 누르면 0.6초 동안 눈앞으로 다가와 살펴보기 상태가 되며, 다시 E키를 누르면 원래 자리로 정확히 돌아간다. 갑툭튀 없는 긴장감 톤에 맞춰 모든 움직임은 천천히 부드럽게 시작하고 멈춘다.

### 2-1. 상태 흐름

1. **Idle**: 평소 상태. 바라보기 감지만 한다.
2. **Focused**: 조준점이 양피지에 닿음. 안내 `[E] 살펴보기` 표시 + 은은한 강조.
3. **MovingIn**: E키 입력 후 눈앞으로 이동 중. 입력 무시.
4. **Inspecting**: 눈앞에서 정지. 마우스 이동으로 회전. E키 또는 Esc로 복귀 시작.
5. **MovingOut**: 원래 자리로 이동 중. 입력 무시. 끝나면 Idle.

### 2-2. 바라보기 감지 (InteractionController 확장)

- 0단계에서 확인한 `InteractionController`에 레이캐스트 감지를 추가한다. 매 프레임 카메라 중앙에서 앞으로 `maxLookDistance = 2.0m` 레이를 쏘고, 맞은 콜라이더의 부모 쪽에서 `IInteractable`을 찾는다.
- 레이어 마스크를 Inspector에서 지정할 수 있게 하고, 트리거 콜라이더는 무시한다(`QueryTriggerInteraction.Ignore`).
- 기존 PhotoSpot(트리거 방식)은 그대로 동작해야 한다. 둘 다 E키를 쓰므로, 동시에 해당되면 조준점이 가리키는 단서를 우선하는 것을 기본안으로 하고 0단계 보고에서 확인받는다.
- 다른 상호작용(사진 촬영 모드 등)이 진행 중이면 감지와 입력을 막는다.

### 2-3. 입력

- 상호작용 입력은 기존 `Player/Interact` 액션(E키) 하나만 쓴다. 바인딩은 추가하거나 바꾸지 않는다. 지난 결정(상호작용은 E키 하나로 통합)을 그대로 따른다.
- 마우스는 조준(무엇을 가리키는지)과 살펴보기 중 회전에만 쓴다. 마우스 클릭은 이 기능에서 쓰지 않는다.
- E키가 활성화되는 조건: 조준점이 `maxLookDistance` 안의 단서를 가리킬 때만 안내 `[E] 살펴보기`가 뜨고 E 입력을 받는다. 단서를 가리키지 않을 때 누른 E는 단서에 아무 영향을 주지 않는다.
- 살펴보기 중에는 E 또는 Esc로 복귀한다(기존 Esc = 취소/나가기 규칙과 동일).

### 2-4. InspectableClue 컴포넌트 (`IInteractable` 구현)

`parchmentFbx`의 **최상위 오브젝트**에 붙인다(자식 메시가 아니라 함께 움직일 루트).

| Inspector 항목 | 기본값 | 설명 |
| --- | --- | --- |
| clueData | Clue\_Parchment\_01 | 이 오브젝트가 주는 단서 데이터 |
| promptText | 살펴보기 | 안내에 표시할 동작 이름 |
| inspectDistance | 0.45 | 카메라 앞 거리 (m) |
| inspectFitSize | 0.30 | 살펴볼 때 가장 긴 변이 이 크기가 되도록 스케일 조정 (m). 0이면 크기 유지 |
| inspectRotationOffset | (0, 0, 0) | 카메라를 바라볼 때 추가 회전 (도). 말린 원통이 화면을 가로로 눕도록 조정 |
| moveDuration | 0.6 | 다가오기/돌아가기 시간 (초) |
| moveCurve | EaseInOut | 움직임 곡선 (AnimationCurve) |
| rotateSensitivity | 0.15 | 마우스 1픽셀당 회전 (도) |

| onInspectStarted / onInspectEnded | 비어 있음 | UnityEvent. 나중에 펼침 연출을 연결할 자리 |

**동작 규칙**

- 다가오기 전에 원래 부모, 위치, 회전, 스케일을 저장하고, 돌아갈 때 그 값으로 정확히 복원한다(오차 0.001m 이하).
- 이동은 위치는 Lerp, 회전은 Slerp, 스케일은 Lerp에 moveCurve를 적용한다. 코루틴으로 처리하고, 진행 중 다시 요청이 오면 무시한다.
- 살펴보는 동안 오브젝트의 콜라이더를 끄고(레이캐스트에 다시 맞지 않게), Rigidbody가 있으면 Kinematic으로 바꾼 뒤 복귀 시 원래 값으로 되돌린다.
- 살펴보는 동안 플레이어 이동과 시점 회전을 멈춘다. 0단계에서 확인한 기존 방식이 있으면 그것을 쓴다. 커서는 잠금 상태 그대로 두고 마우스 이동량(Look 액션)으로 오브젝트를 회전한다. 좌우는 카메라 위쪽 축, 위아래는 카메라 오른쪽 축 기준.
- 안내 UI는 MovingIn 시작 시 숨기고, 살펴보기 중에는 화면 아래에 `[E] 내려놓기  [마우스] 돌려보기`를 작게 표시한다.

### 2-5. 강조 표시 (Focused)

- `MaterialPropertyBlock`으로 기본 색을 약 1.15배 밝게 한다. 머티리얼 인스턴스를 만들지 않기 위함이다. URP Lit은 `_BaseColor`를 쓴다.
- 0.15초 동안 서서히 켜지고 꺼지게 한다. 번쩍이는 효과는 쓰지 않는다.

### 2-6. 살펴보기 배경 연출

- 새 Volume `Inspect_Volume`(Global, 우선순위는 기존 뷰파인더 Volume과 겹치지 않게)을 만들고, weight를 moveDuration 동안 0→1, 복귀 시 1→0으로 바꾼다.
- 프로필: Depth of Field(Gaussian, 시작 0.6m 정도로 배경만 흐리게), Vignette 0.3, Color Adjustments 채도 −20. 조용하고 집중되는 느낌을 목표로 하며 수치는 보고 후 조정한다.
- 벽에 붙어서 살펴볼 때 양피지가 벽을 뚫고 보이는지 확인한다. 문제가 있으면 Overlay 카메라 방식을 제안만 하고 구현하지 않는다.

### 2-7. 단서 데이터와 획득

- `ClueData` (ScriptableObject): `clueId`(문자열, 중복 금지), `displayName`, `description`(여러 줄). 이번에는 이 세 개만 만든다.
- `ClueJournal` (MonoBehaviour, 씬의 관리 오브젝트에 하나): 획득한 clueId 목록, `bool TryAcquire(ClueData)`, `bool HasClue(string)`, `event Action<ClueData> OnClueAcquired`.
- 처음 살펴보기에 들어가는 순간 `TryAcquire`를 호출하고, 처음일 때만 토스트로 `단서 획득: {displayName}`을 띄운다. `PhotoAcquiredToast`를 범용으로 쓸 수 있으면 재사용하고, 바꿔야 하면 0단계에서 보고한다.
- 네트워크 동기화는 하지 않지만, 나중에 "획득 상태"만 보낼 수 있도록 획득 처리는 ClueJournal 한 곳에서만 일어나게 한다.

## 3단계: 에디터 설정 / 4단계: 플레이 테스트

코드가 컴파일 에러 없이 끝나면, 사용자가 손으로 할 필요 없도록 Unity MCP로 에디터 설정까지 직접 한다. 각 항목을 마친 뒤 결과를 확인하고 다음으로 넘어간다.

### 3단계: 에디터 설정 (Unity MCP)

1. 0단계에서 승인된 경우 정점 세분화를 실행하고, 결과 메시를 양피지 MeshFilter에 연결한다.
2. FBX 임포트 설정에서 Read/Write Enabled를 켠다(빌드에서 메시 정점을 읽으려면 필요).
3. 메시 오브젝트에 `ParchmentRoller`를 추가하고 축 설정과 기본값을 넣은 뒤 rollAmount = 1로 둔다.
4. 메시 오브젝트에 BoxCollider가 없으면 추가한다(ParchmentRoller가 크기를 자동으로 맞춘다).
5. `Assets/Data/KJH/Clue/Clue_Parchment_01.asset`을 만든다. clueId = `parchment_01`, displayName = `낡은 양피지`, description = `(임시) 내용 미정`.
6. `parchmentFbx` 최상위에 `InspectableClue`를 추가하고 clueData를 연결한다.
7. 씬에 `ClueJournal`이 붙은 관리 오브젝트가 없으면 만든다(기존 관리 오브젝트가 있으면 거기에 붙인다).
8. `InteractionController`의 레이어 마스크, 최대 거리를 설정한다.
9. `Player/Interact`의 바인딩은 바꾸지 않는다. E키로 되어 있는지 확인만 한다.
10. `Inspect_Volume`과 프로필을 만들고 weight = 0으로 둔다.
11. 씬을 저장한다.

### 4단계: 플레이 테스트 (Unity MCP)

| 번호 | 테스트 | 통과 기준 |
| --- | --- | --- |
| T1 | 에디터 모드에서 rollAmount 0 / 0.5 / 1 스크린샷 | 겹이 뚫리지 않고 텍스처가 찢어지지 않음 |
| T2 | 씬 저장 후 다시 열기 | 말린 상태 유지, 메시 누락 경고 없음 |
| T3 | 플레이어를 양피지 앞 1.5m에 두고 카메라가 양피지를 향하게 함 | Focused 상태, 안내 표시, 강조 켜짐 |
| T4 | 조준을 양피지에서 벗어나게 함 / 2m 밖으로 이동 | 안내와 강조가 서서히 꺼짐 |
| T5 | 상호작용 입력 호출 | MovingIn → Inspecting, 카메라 앞 0.45m 위치, 플레이어 이동·시점 회전 멈춤 |
| T6 | 살펴보기 중 마우스 이동 값 주입 | 오브젝트가 회전, 위아래 80도에서 멈춤 |
| T7 | 다시 상호작용 입력 (그리고 Esc로 한 번 더) | 원래 위치·회전·스케일과 오차 0.001 이하, 콜라이더·Rigidbody 복원 |
| T8 | T5\~T7 3회 반복 | 위치가 조금씩 어긋나지 않음, 토스트는 첫 회에만 |
| T9 | 이동 중(MovingIn/Out)에 입력 연타 | 무시되고 상태가 꼬이지 않음 |
| T10 | 기존 PhotoSpot에서 E로 진입 → 촬영 → Esc | 기존과 동일하게 동작, PhotoSpot 안에서 단서를 바라볼 때는 단서가 우선 |
| T11 | 전체 테스트 후 콘솔 확인 | 에러·경고 0건 |

MCP로 직접 할 수 없는 테스트(예: 실제 마우스 감각)는 무엇을 대신 확인했는지 적고, 사용자가 직접 확인할 항목으로 따로 보고한다.
